# 解锁与回程(妙妙屋X)

全程只读。两项数据都来自主控的**定时检测**,不是现场测的结果。

## A. 解锁

1. `node_unlock_list`(不带参数):每个节点的摘要 —— 解锁了几项 / 共几项。
2. `node_unlock_list`(`node_id`):该节点逐项的结论和地区(Netflix、Disney+、ChatGPT、Claude、Gemini 等)。
3. 回答「哪些节点能用某项服务」时,先取摘要定位候选,再逐个取明细核对那一项,不要只看总数。

解读时注意:

- 检测的是节点**出口**的 IP。转发 / 中转节点看的是落地机,不是入口机。
- 某个节点上只对部分用户生效的分流(例如 AI 分流到另一个落地),不代表整台机器都解锁。
- 状态是「页面认不出 / 网络失败」不等于不可用,只是这次没测出来。
- 结果每天更新一次。刚换出口或刚改分流,要等下一轮检测才会变。

## B. 三网回程

1. `node_return_routes`:
   - `enabled=false`:回程测试没开(系统设置里开),此时没有数据。
   - `servers`:每台服务器的三网(电信 / 联通 / 移动)回程线路与奖牌(`gold` 有优质线路,`silver` 认出了线路但都普通)。
   - `nodes`:节点 ID → 服务器 ID **列表**。
2. 回程看的是**客户端实际连的那台**:普通节点是它所在的服务器;转发链 / 中转节点是**入口机**,不是落地机。
3. 一个节点对应多台服务器,说明它是转发链节点、入口组有多台且用域名接入 —— 客户端可能连到其中任何一台,几台的回程都要报给用户。

## 给用户推荐节点时

- 解锁看落地,回程看入口,两者不是同一台机器,分开说。
- 没有检测记录的节点如实说「没测过」,不要推断。
