# 路由出站子节点(妙妙屋X)

目标:在一个**父节点**(中转 / 入口)下挂一个或多个**落地**,让套餐里分配了子节点的用户连父节点的地址、流量从落地出去。

## 概念

- **父节点**:客户端实际连的那个节点,必须是物理节点(`node_list` 里 `node_type` 为空或 `physical`),不能是另一个路由出站。
- **落地节点**:流量最终出去的节点。它可以是本面板任何一台服务器上的节点。
- **子节点**:建出来之后在节点列表里是一条独立的节点(名字默认「父节点名-label」),可以单独加进套餐。只有套餐里有它的用户才会被分流到这个落地;父节点上的其他用户不受影响。
- **label**:只能是 `[a-zA-Z0-9-]`、长度 2-32、同一父节点下不能重复。出站 tag 由它派生(`routed:p<父节点ID>:<label>`),**建好后不能改**,只能改显示名。

## A. 挂一个落地

1. `node_list` 找到父节点和落地节点的 ID。
2. `routed_outbound_list`(`parent_id`)看父节点下已有哪些子节点,别重复建。
3. `routed_outbound_create`:`parent_node_id` + `label` + `from_node_id`(落地节点 ID)。
   - **只给 `from_node_id` 就够了**:出站配置和凭据由主控按落地节点的真实入站推导。不要自己拼 `outbound`,除非落地不是本面板的节点。
4. 把新子节点加进套餐(`package_update` 的 nodes 里加上它的 ID),用户才用得到。

## B. 一次挂多个落地

用 `routed_outbound_batch_create`:`parent_node_id` + `from_node_ids`(数组,**按想要的顺序排**)。

- 主控**逐个**创建,label 自动生成。不能并发:每个都要改父入站的用户表和路由规则。
- **中途失败即停**:返回里 `results` 列出每个的结果,失败的那个带原因,它后面的没有动。修掉原因后,只对剩下的再调一次(不要把已成功的再传一遍,会多建一份)。

## C. 改名与删除

- `routed_outbound_rename`(`id` + `node_name`):只改显示名,凭据和路由不变,用户不用重新导入。
- `routed_outbound_delete`(`id` + `confirm: true`):摘掉子节点及各用户在它上面的子账号。套餐里分配了它的用户立刻用不了这条线,删之前先告诉用户影响范围。

## D. 只想让部分域名走落地(AI 分流)

子节点是「整个用户的流量都走落地」。如果要的是「同一个用户,只有 AI 网站走落地」,那是**节点路由规则**,不是子节点:

1. `routing_rule_preset_list` 看有没有现成的域名预设。
2. `server_routing_get`(父节点所在服务器)读当前路由,在其中加一条 `domain → outboundTag` 的规则,`outboundTag` 用已建好的子节点的出站 tag。
3. `server_routing_update` 写回。改之前把现有规则原样带上,这是覆盖式更新。

## 排障

- **创建报「读取落地节点的入站失败 / 502」**:落地节点所在服务器离线。`server_list` 确认状态。
- **创建报「已达到许可证节点数量上限」**:路由出站和物理节点共用配额,`license_status` 看上限。
- **用户连得上父节点但不走落地**:`user_subaccounts`(用户名)看他在这个子节点上有没有子账号;没有说明套餐里没分配到这个子节点。
- **落地在 NAT 后面连不上**:见 `mmwx-reverse-tunnel`。

## 注意

- 建、删都会改父节点所在服务器的 xray 配置,父节点所在服务器必须在线。
- 删除是高危操作,需要 `confirm: true`。
